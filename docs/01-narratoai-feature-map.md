# NarratoAI 功能拆解（基准版本 v0.8.6）

> 目的：在做 1:1 之前，把它“到底是什么、怎么跑、产出什么”拆到可实现的程度。
> 依据：仓库源码 `linyqh/NarratoAI@main`（已 clone 到 `_research/NarratoAI`）、`config.example.toml`、`webui/`、`app/services/`、prompts。
> 本文只描述**现状**；我们的改造与增强放在 `02-product-design.md`。

---

## 1. 产品形态

| 维度 | 现状 |
|---|---|
| 定位 | 一站式 AI 影视解说 + 自动化剪辑 |
| 技术栈 | Python 3.12 + Streamlit 单页 Web（`127.0.0.1:8501`） |
| 交付 | Windows/macOS 整合包、Docker、`uv` 本地运行 |
| 配置 | `config.toml`，UI 内可改；`hide_config` 控制是否暴露 |
| 输入 | 本地视频（上传或路径）+ 字幕（上传 SRT / Fun-ASR 转写） |
| 输出 | 成片 MP4（烧录字幕、BGM、配音）+ 剪映草稿 + 脚本 JSON |
| 状态 | 单任务同步执行，Streamlit 进度条；无任务队列/断点续跑 UI |

它的 UI 不是“剪辑软件”，而是**一张参数表单 + 一个生成按钮**：左列脚本、中列音频、右列视频/字幕，全部展开在首屏。

## 2. 五种创作模式（UI 里的「视频类型」）

| 模式 | 输入 | 中间产物 | 输出 | 关键差异 |
|---|---|---|---|---|
| **影视解说** `film_summary` | 视频 + 字幕 | 剧情理解 → 解说文案 → 片段规划 → 解说脚本 | 成片 / 剪映草稿 | OST 0/1/2 混排，原片占比可调，多集 |
| **短剧解说** `summary` | 视频 + 字幕 | 同上 | 同上 | 短剧类型预设；**Tavily 联网检索**剧名补充人物/分集；多集跨集拼接 |
| **自动生成**（纪录片）`auto` | 仅视频（无字幕） | 抽帧 → 视觉模型逐批描述 → 解说脚本 | 成片 | 不依赖字幕；适合纪录片/动物/荒野建造；无原声台词 |
| **短剧混剪** `short` | 视频 + 字幕 | 剧情点 → N 个原声片段 | 纯混剪成片 | 不写文案、不配音；`OST` 恒为 1；`custom_clips` 控制片段数 |
| **选择/上传脚本** `file` | 视频 + `items` JSON | — | 成片 / 草稿 | 跳过 AI，直接 TTS + 合成；可手改 JSON |

> 「短句解说」在 NarratoAI 里不是独立模式，而是**解说文案的写法约束**：文案按“一句一个信息点、15–35 字”输出，再由片段规划把每句匹配到画面；`OST=0` 的片段按 TTS 时长裁剪。我们要把它提升为显式模式与可调密度。

## 3. 核心数据模型（整个软件的“宪法”）

解说脚本是一个 `items` 数组，每个元素 = 一个镜头：

```json
{
  "_id": 1,
  "video_id": 1,
  "video_name": "1.mp4",
  "timestamp": "00:00:01,000-00:00:05,500",
  "picture": "男主站在审讯室门口，神情紧张地看向桌上的证据袋",
  "narration": "他以为这只是一次普通问询，可桌上的证据却把所有矛头指向了自己。",
  "OST": 0
}
```

| 字段 | 语义 | 约束 |
|---|---|---|
| `_id` | 镜头序号 | 从 1 连续递增；配音/裁剪/字幕都用它做映射 |
| `video_id` / `video_name` | 来源视频 | 多集时定位素材；时间戳是**该视频内部**的局部时间 |
| `timestamp` | `HH:MM:SS,mmm-HH:MM:SS,mmm` | 必须来自字幕真实时间轴，禁止用拼接后的全局时间 |
| `picture` | 画面描述 | 用于人工核对与素材定位 |
| `narration` | 解说词 | `OST=1` 时固定写「播放原片{_id}」 |
| `OST` | 音轨类型 | `0` 纯解说（去原声）/ `1` 纯原声 / `2` 解说+原声 |

**OST 三态决定一切后处理**：

| OST | 画面时长 | 原声 | 配音 | 用途 |
|---|---|---|---|---|
| 0 | = TTS 音频时长 | 移除 | 有 | 叙事主线、钩子、转场 |
| 1 | = timestamp 长度（3–10s 建议） | 保留 | 无 | 名场面、关键对白、反转 |
| 2 | = TTS 音频时长 | 保留（压低） | 有 | 情绪段落、边讲边看 |

## 4. 完整流水线（影视/短剧解说）

```
字幕输入 → 剧情理解 → 解说文案(可审) → 片段规划 → 脚本文案生成 → 校验/修复
        → 逐条 TTS → 逐段裁剪 → 音频/字幕合并 → 成片合成 → 剪映草稿
```

### 4.1 字幕输入
- 上传 SRT；或 Fun-ASR 转写，三种后端：
  - 本地 `FunASR-Pack`（`127.0.0.1:7860`）
  - 本地 `FireRedASR2-AED-Pack`（`:7867`）
  - 阿里百炼在线 `fun-asr`（API Key）
- 支持热词、说话人分离；多文件字幕合并预览。
- 字幕工具：**批量翻译**（每批 20 条、并发 3）、**字幕校准**、原文/译文预览。
- 原始字幕可只作为“理解材料”，不参与成片字幕。

### 4.2 剧情理解
输入：整段字幕（带 `视频 N: 文件名` 分段标题 + 局部时间戳）、剧名、类型；可选 Tavily 联网检索补充公开剧情。
输出：结构化剧情材料（人物关系、主线、分集脉络、钩子点），展示在可编辑文本框里，供后续两步复用。
缓存签名 = `字幕路径集 + 剧名 + 联网开关 + 视频路径集`，任一变化即失效。

### 4.3 解说文案（Human-in-the-loop 的关键）
- 纯文本输出，**不带时间戳、不带编号、不输出 JSON**，方便人改。
- 参数：剧名、类型（剧情/情感、悬疑/犯罪、动作/冒险、喜剧、科幻、历史、恐怖、自定义）、解说语言（多语言 + 自定义）、目标字数（步进 50）。
- 写作约束：开头钩子 =「人物困境 + 反常信息 + 悬念问题」；每句一个信息点；单句 15–35 字；每 2–3 句有承接；总字数 ±10%。
- 用户可改、可重写，改完再进入匹配——这是它效果稳定的核心设计。

### 4.4 片段规划
输入：剧情理解 + 字幕 + 解说语言 + 类型。
输出：`segments[]`（只有 `_id/video_id/video_name/timestamp/OST/story_role/intent/transition`）。
硬规则：
- 开场必须是 `OST=0` 钩子；原声单段 3–10s；禁止连续 3 个 `OST=1`；每 1–2 个原声后必须有解说承接。
- 跨集切换必须有 `OST=0` 桥段。
- 剔除片头、片尾、演职员表、广告、预告、花絮、水印、扫码/会员等非剧情片段。
- 时长预算：`解说字数 / 5 ≈ 所需秒数`；短画面不许压长文案。

### 4.5 脚本文案生成
- 只能补 `picture` / `narration`，**不许改** `_id/video_id/video_name/timestamp/OST`。
- 数量、顺序必须与规划一致（除广告片段被删）。
- `OST=1` 的 `narration` 写「播放原片{_id}」；`OST=0` 必须用目标语言。
- 原片占比（默认 30%）通过规划阶段控制，而不是事后按比例删。
- 输出严格 JSON。

### 4.6 校验 / 修复
- `check_format` 校验字段、时间戳、`OST`、`_id` 连续性。
- 失败时把确定性错误回灌给 LLM 做**定向修复**，再校验；仍失败则报错并保留可编辑 JSON。

### 4.7 配音
- 逐条合成，返回 `audio_file` + `duration` + `subtitle_file`。
- 11 个引擎（见 §6），云端 + 本地混合；本地引擎通过 HTTP Pack 调用。
- 时长回写脚本，驱动后续裁剪；支持语速/音量/音调。

### 4.8 裁剪（音画对齐的核心）
| OST | 裁剪方式 | 音轨 |
|---|---|---|
| 0 | 起点 = timestamp 起点，终点 = 起点 + TTS 时长 | `-an` 去音轨 |
| 1 | 严格按 timestamp 起止 | 保留原声 |
| 2 | 起点 + TTS 时长 | 保留原声 |
- ffmpeg 快速定位（`-ss` 前置 + `-t`），硬件编码优先（NVENC/QSV/AMF/VideoToolbox），失败多级回退到 libx264。
- 片段命名 `ost{0|1|2}_{id}_vid_{start}@{end}.mp4`，天然可缓存/可排查。

### 4.9 合并
- 视频按 `_id` 顺序拼接；音频轨 = 配音（1.0）+ 原声（1.2）+ BGM（0.3）。
- **智能音量**：分析 TTS 与原声响度，自动配平后再叠 BGM。
- 字幕：优先 ASS 烧录（字体/字号/颜色/描边/位置），退化到 drawtext / PNG 叠加。
- **原字幕遮盖**：横屏、竖屏两套区域参数（x/y/宽/高/模糊半径/不透明度），先模糊再压暗，再烧新字幕。
- 输出 30fps；有 `ffmpeg` 快速路径，失败回退 MoviePy。
- 可选 AI 配乐 / AI 音效（Sonilo，上传成片生成，失败自动回退/跳过）。

### 4.10 剪映草稿导出
- 生成 `draft_content.json` + `draft_meta_info.json` + 素材副本。
- 轨道：视频轨（按片段切分、含音量）、音频轨（TTS）、文本轨（字幕，字体/字号/颜色/描边/位置映射）。
- 支持画布比例（原始/16:9/9:16/1:1）、草稿命名、目标目录校验。
- 素材路径做相对化与去重，避免剪映“素材丢失”。

## 6. TTS 引擎矩阵

| 引擎 | 部署 | 说明 |
|---|---|---|
| Edge TTS | 云端（免费） | 默认，音色多，限流需重试 |
| Azure Speech | 云端 | 需 key/region |
| 腾讯云 TTS | 云端 | secret_id/key |
| 通义 Qwen3-TTS | 云端 | DashScope |
| 豆包 TTS | 云端 | 新版 API Key / 旧版 appid+token |
| IndexTTS-1.5 | 本地 | 零样本克隆，参考音频 |
| IndexTTS-1.5 macOS | 本地 MLX | Apple Silicon |
| IndexTTS-2 MLX | 本地 | 情绪控制 |
| OmniVoice | 本地 | auto / voice_design / voice_clone |
| VoxCPM-0.5B | 本地 | 轻量 |
| VoxCPM-2B | 本地 | 音色设计 + 克隆 |

所有本地引擎都是**独立 HTTP 服务**（不同端口），主程序只做客户端——这对我们很关键：Tauri 侧同样用 HTTP sidecar，不必把模型塞进 Rust。

## 7. 多视频 / 多集

- 支持一次选多个视频，每集单独设截取范围。
- 字幕分段标题带 `视频 N: 文件名`，脚本里 `video_id + video_name` 绑定来源。
- 时间戳是**集内局部时间**，不是拼接后的全局时间；跨集必须靠 `OST=0` 桥接。
- 多集合并时做编码/分辨率统一，避免拼接报错。

## 8. 工程化能力

- 任务进度 + 分阶段日志（`loguru`），失败有中文提示。
- FFmpeg 引擎检测（整合包/系统/自定义）、硬件加速探测、字幕滤镜与 ASS 能力检测。
- 缓存清理：抽帧、裁剪片段、任务临时目录。
- 中英双语 i18n；模型/引擎/Key 配置持久化。
- 多处重试与降级：LLM 超时/限流、TTS 重试、编码器回退、Sonilo 失败回退。

## 9. 现状短板（我们的机会点）

1. **单页表单**：参数一屏堆叠，首次使用认知负担极高；无步骤感。
2. **没有时间轴/分镜表**：只能改 JSON 表格，看不到“画面 + 解说 + 配音”的关系。
3. **没有逐句精修**：文案是整段 textarea，无法单句改写、单句重配画面。
4. **没有任务队列**：一次只能跑一个，多集批量要人守着。
5. **没有断点续跑**：失败要从头再来（虽然后端有部分缓存）。
6. **没有素材导入链接**：只支持本地文件（`youtube_service` 未接入 UI）。
7. **状态不可见**：配音/裁剪/合并进度只有一个总进度条，出错难定位。
8. **无快捷键、无深色主题、无高 DPI 适配**（Streamlit 限制）。

## 10. 1:1 对齐清单（我方模块 → 能力）

| 优先级 | 模块 | 必须对齐 |
|---|---|---|
| P0 | 项目/素材 | 多视频多集、截取范围、字幕导入、SRT 解析、项目持久化 |
| P0 | 脚本流水线 | 剧情理解、解说文案（可审）、片段规划、脚本生成、校验修复、5 种模式 |
| P0 | 配音 | Edge TTS + 至少 2 个云端 + 1 个本地克隆；逐条合成、时长回写、试听 |
| P0 | 合成 | OST 0/1/2 裁剪、音画对齐、原声/配音/BGM 混音、字幕烧录、比例、硬件加速回退 |
| P0 | 导出 | 成片 MP4、剪映草稿、SRT/文案/JSON |
| P1 | 字幕工具 | Fun-ASR 本地/在线、翻译、校准、原字幕遮罩 |
| P1 | 模型接入 | OpenAI 兼容多供应商、Gemini、TwelveLabs 视觉、Tavily |
| P1 | 设置 | 模型/引擎/路径/缓存/代理/语言 |
| P2 | 增强 | 链接下载、任务队列、断点续跑、时间轴编辑、批量、快捷键 |

> 「1:1」的验收口径：**同一部片、同一套参数，产出的 items 结构、OST 分布、成片节奏与剪映草稿轨道结构一致**；文案质量由提示词与模型决定，允许差异。
